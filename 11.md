# Wha11y

## Structure

### Make information clear and easy to follow

Use clear titles, sections, and other structures to help people understand and navigate the content.

**Web browser**

1. Open the page.
2. Check that the page has a clear and meaningful title.
3. Check that the main content is divided into clear sections.
4. Check that headings are visually and logically distinguishable.
5. Check that the page language is appropriate.
6. If the structure is unclear, use the browser's accessibility tools to investigate further.

**Android app**

1. Open the screen.
2. Check that the purpose of the screen is immediately understandable.
3. Check that the main content is divided into clear sections.
4. Check that titles and headings are easy to identify.

**iOS app**

1. Open the screen.
2. Check that the purpose of the screen is immediately understandable.
3. Check that the main content is divided into clear sections.
4. Check that titles and headings are easy to identify.

**Office document**

1. Open the document.
2. Check that it has a clear main title.
3. Check that sections are clearly identified.
4. Check that headings are used consistently.
5. Check that lists are presented as lists rather than as manually formatted text.
6. Use the built-in accessibility checker if available.

**Design / Mockup**

1. Check that the page title is clearly identifiable.
2. Check that sections and headings have a clear visual hierarchy.
3. Check that lists and groups of information are visually understandable.

When the technical structure cannot be determined from the mockup, specify the intended structure, such as page title, heading level or list.

---

### Put information and actions in a logical order

Present information and actions in an order that makes sense and is easy to follow.

**Web browser**

1. Open the page.
2. Use the keyboard to move through the main content and interactive elements.
3. Check that the order follows a logical sequence.
4. Check that no important information or action is unexpectedly skipped.
5. If the order seems incorrect, investigate with browser accessibility tools.

**Android app**

1. Open the screen.
2. Follow the content from the beginning to the end using normal touch navigation.
3. Check that information is presented in a logical order.
4. Check that actions appear at the appropriate point in the user journey.

**iOS app**

1. Open the screen.
2. Follow the content from the beginning to the end using normal touch navigation.
3. Check that information is presented in a logical order.
4. Check that actions appear at the appropriate point in the user journey.

**Office document**

1. Read the document from beginning to end.
2. Check that sections follow a logical sequence.
3. Check that images, tables, columns and other elements appear in the expected place.
4. Check the reading order using the application's accessibility tools when available.

**Design / Mockup**

1. Follow the visual reading flow from the beginning to the end.
2. Check that the order of information and actions makes sense.
3. Check that important actions appear at the appropriate point in the flow.

If the technical reading or interaction order may differ from the visual order, specify the intended order.

## Content

### Provide alternatives when content cannot be seen or heard

Provide appropriate alternatives for images, audio, video, and other content that some people may not be able to see or hear.

**Web browser**

1. Identify every image that conveys information.
2. Check that each meaningful image has an appropriate text alternative.
3. Identify videos or audio that convey information.
4. Check that captions, transcripts or another appropriate alternative are provided when needed.
5. Mark purely decorative images as decorative so they do not need unnecessary alternative text.

**Android app**

1. Identify images that convey information.
2. Check that users can obtain the same essential information without seeing the image.
3. Check videos for captions or another appropriate alternative when needed.

**iOS app**

1. Identify images that convey information.
2. Check that users can obtain the same essential information without seeing the image.
3. Check videos for captions or another appropriate alternative when needed.

**Office document**

1. Identify every image that conveys information.
2. Check that meaningful images have appropriate alternative text.
3. Check audio and video content.
4. Check that an appropriate text alternative, caption or transcript is provided when needed.
5. Mark decorative images appropriately.

**Design / Mockup**

1. Identify every image, icon, audio or video that conveys information.
2. Decide what information a person would need if they could not see or hear it.
3. Specify the alternative text or equivalent information.
4. Identify decorative images that do not need an alternative.
5. For video or audio, specify whether captions, a transcript or another alternative is required.

---

### Give people control over moving or changing content

When content moves, plays, or changes automatically, give people a way to control, pause, or stop it.

**Web browser**

1. Use the page normally.
2. Identify animations, carousels, auto-playing media and automatically changing content.
3. Check whether the user can pause, stop or control the content.
4. Check that controls remain available while the content is playing or changing.

**Android app**

1. Use the screen normally.
2. Identify animations, auto-playing media and automatically changing content.
3. Check that appropriate controls are available.
4. Check that the user can stop or pause the content when necessary.

**iOS app**

1. Use the screen normally.
2. Identify animations, auto-playing media and automatically changing content.
3. Check that appropriate controls are available.
4. Check that the user can stop or pause the content when necessary.

**Office document**

1. Review the document for animations, media or automatically changing content.
2. Check that the user has appropriate control over this content.
3. Check that essential information is not dependent on content changing automatically.

**Design / Mockup**

1. Identify any content that moves, plays or changes automatically.
2. Design the controls needed to pause, stop, replay or otherwise control it.
3. Design the relevant states of these controls.
4. Specify the expected behavior when the user interacts with them.

## Visuals

### Make text and important information easy to see

Make text and important information clearly visible and easy to distinguish from the background.

**Web browser**

1. Open the page.
2. Check that normal text is easy to read against its background.
3. Check that important information is clearly distinguishable.
4. Use a contrast checker to verify the colors when needed.
5. Check that text remains readable when the browser zoom is increased.

**Android app**

1. Open the screen in normal conditions.
2. Check that text is easy to read against its background.
3. Check that important information is clearly visible.
4. Use a contrast checker for precise verification when needed.

**iOS app**

1. Open the screen in normal conditions.
2. Check that text is easy to read against its background.
3. Check that important information is clearly visible.
4. Use a contrast checker for precise verification when needed.

**Office document**

1. Review text throughout the document.
2. Check that text is clearly visible against its background.
3. Check headings, links, tables and other important information.
4. Use a contrast checker when needed.

**Design / Mockup**

1. Check that text is easy to read.
2. Check that important information stands out clearly from the background.
3. Use a contrast checker to verify the colors.
4. Check different states such as normal, hover, selected or disabled when they exist.

Specify any contrast requirement that cannot be determined directly from the mockup.

---

### Do not use color as the only way to give information

Never use color as the only way to communicate information, meaning, status, or instructions.

**Web browser**

1. Identify information communicated through color, such as errors, warnings, status or selection.
2. Check that the same information is also communicated through text, an icon, a shape or another visual cue.
3. If possible, inspect the page in grayscale.
4. Repeat the check for different states.

**Android app**

1. Identify information communicated through color.
2. Check that another visual or textual indication provides the same information.
3. Check important states such as errors, warnings and selections.

**iOS app**

1. Identify information communicated through color.
2. Check that another visual or textual indication provides the same information.
3. Check important states such as errors, warnings and selections.

**Office document**

1. Identify information communicated only through color.
2. Check that another visual or textual indication is also provided.
3. Review the document in grayscale when useful.

**Design / Mockup**

1. Review the design in grayscale.
2. Identify every situation where color communicates meaning.
3. Check that the same meaning is communicated through text, an icon, shape, pattern or another visual cue.
4. Repeat the check for all relevant states.

Specify the additional indicator when it is not obvious from the design.

## Adaptability

### Make content work for different needs and screen sizes

Make sure content remains usable when people change its size, orientation, or other aspects of how it is displayed.

**Web browser**

1. Open the page.
2. Increase the browser zoom to at least 200%.
3. Check that information remains visible and usable.
4. Check that content does not overlap or disappear.
5. Check that important actions remain accessible.
6. Check different screen sizes when relevant.

**Android app**

1. Open the application settings.
2. Increase the text size.
3. Return to the application and check that content remains readable and usable.
4. Check that important information and actions are still available.
5. Test different screen orientations when relevant.

**iOS app**

1. Open the device settings.
2. Increase the text size.
3. Return to the application and check that content remains readable and usable.
4. Check that important information and actions are still available.
5. Test portrait and landscape when relevant.

**Office document**

1. Increase the text size or use the available display settings.
2. Check that text remains readable.
3. Check that content does not overlap or disappear.
4. Check that important information and actions remain accessible.

**Design / Mockup**

1. Review all screen sizes and responsive layouts provided.
2. Check how content adapts when the available space becomes smaller or larger.
3. Check that text can grow without hiding important information.
4. Check that orientation changes are considered when relevant.

Specify the expected behavior when content is enlarged, resized or displayed in another orientation.

## Interactions

### Let people use the content in different ways

Make content and functionality usable through different ways of interacting, without requiring a single specific method.

**Web browser**

1. Use the keyboard to perform the main actions.
2. Check that links, buttons, fields and other essential functions can be reached without a mouse.
3. Check that the keyboard does not get trapped in one part of the page.
4. Check that the current position is visible while navigating with the keyboard.
5. Use other interaction methods when they are relevant to the feature being tested.

**Android app**

1. Perform the main actions using normal touch interaction.
2. Check whether an action depends on a specific gesture.
3. Where a complex gesture is required, check that a simpler alternative is available when appropriate.

**iOS app**

1. Perform the main actions using normal touch interaction.
2. Check whether an action depends on a specific gesture.
3. Where a complex gesture is required, check that a simpler alternative is available when appropriate.

**Office document**

1. Perform the main actions available in the document.
2. For interactive documents, use the keyboard to navigate and operate controls.
3. Check that essential actions do not depend on a single specific method of interaction.

**Design / Mockup**

1. Identify the main ways users are expected to interact with each component.
2. Check that the design does not require an unnecessarily specific interaction method.
3. Identify actions that may need an alternative way to operate.

Specify alternative interaction requirements when they cannot be demonstrated in the mockup.

### Make buttons, links, and other actions easy to find and use

Make buttons, links, controls, and other interactive elements easy to identify, understand, and use, with enough space and a clear purpose.

**Web browser**

1. Open the page.
2. Check that buttons, links and controls are visually identifiable.
3. Check that their purpose is clear.
4. Navigate with the keyboard and check that the current focus is visible.
5. Check that clickable areas are large enough to use comfortably.
6. Check that nearby controls are sufficiently separated.

**Android app**

1. Open the screen.
2. Check that buttons and controls are easy to identify.
3. Check that their purpose is clear.
4. Check that touch areas are large enough to tap comfortably.
5. Check that nearby controls are sufficiently separated.

**iOS app**

1. Open the screen.
2. Check that buttons and controls are easy to identify.
3. Check that their purpose is clear.
4. Check that touch areas are large enough to tap comfortably.
5. Check that nearby controls are sufficiently separated.

**Office document**

1. Check that links, buttons and other interactive elements are easy to identify.
2. Check that their purpose is clear.
3. Check that interactive areas are sufficiently separated.
4. Use the keyboard to verify interactive elements where applicable.

**Design / Mockup**

1. Check that buttons, links and controls are visually identifiable.
2. Check that their purpose is clear from their label or surrounding context.
3. Check that touch targets have sufficient size.
4. Check that nearby targets have sufficient spacing.
5. Design relevant states such as focus, selected, pressed, disabled or expanded/collapsed when applicable.

Specify the intended role, name or behavior when it cannot be determined from the visual design.

## Feedback

### Make it clear what people need to do

Clearly identify fields, choices, links, and actions, and explain what people need to provide or do, including when something is required.

**Web browser**

1. Open every form or interactive area.
2. Check that each field has a visible label.
3. Check that instructions are clear and placed where they are needed.
4. Check that required fields are clearly identified.
5. Check that buttons and links clearly indicate what they do or where they lead.

**Android app**

1. Open each form.
2. Check that every field has a visible and consistent label.
3. Check that instructions are easy to understand.
4. Check that required fields are clearly identified.
5. Check that actions have clear labels.

**iOS app**

1. Open each form.
2. Check that every field has a visible and consistent label.
3. Check that instructions are easy to understand.
4. Check that required fields are clearly identified.
5. Check that actions have clear labels.

**Office document**

1. Review every form or interactive element.
2. Check that fields have clear labels.
3. Check that required information is clearly identified.
4. Check that instructions are understandable.
5. Check that link text clearly describes its destination or purpose.

**Design / Mockup**

1. Check that every field has a visible and understandable label.
2. Check that instructions are clear.
3. Check that required fields are clearly identified.
4. Check that the purpose of buttons, links and actions is clear.

Specify any label, required status or instruction that cannot be determined from the visual design.

### Make mistakes easy to understand and fix

Clearly explain what went wrong and, when possible, help people understand how to correct the problem.

**Web browser**

1. Find a form or action that can generate an error.
2. Submit incomplete or incorrect information.
3. Check that the error is clearly visible.
4. Check that it is clear which field or action caused the error.
5. Check that the message explains what went wrong.
6. Check that the message explains how to correct the problem when possible.

**Android app**

1. Submit incomplete or incorrect information.
2. Check that the error is clearly visible.
3. Check that the affected field is easy to identify.
4. Check that the message explains what went wrong.
5. Check that the message explains how to correct it.

**iOS app**

1. Submit incomplete or incorrect information.
2. Check that the error is clearly visible.
3. Check that the affected field is easy to identify.
4. Check that the message explains what went wrong.
5. Check that the message explains how to correct it.

**Office document**

1. Review forms and fields where applicable.
2. Trigger an error using incomplete or incorrect information.
3. Check that the error is clearly identified.
4. Check that the correction is understandable.

**Design / Mockup**

1. Design the error state for each relevant field or component.
2. Check that the affected element is clearly identified.
3. Provide a clear explanation of what went wrong.
4. Provide a clear indication of how to correct the problem.
5. Design the relevant visual states needed to communicate the error.
